## Changelog Format

Each release includes:

- **Version Number**: Semantic version (MAJOR.MINOR.PATCH)
- **Release Date**: Date of release
- **Features**: New features added
- **Improvements**: Enhancements to existing features
- **Bug Fixes**: Issues resolved
- **Security**: Security updates
- **Deprecations**: Deprecated features
- **Breaking Changes**: Changes that break compatibility
- **Upgrade Notes**: Important upgrade information

## Version Numbering

UAMS follows [Semantic Versioning](https://semver.org/):

- **MAJOR** version: Incompatible API changes
- **MINOR** version: New functionality in a backward compatible manner
- **PATCH** version: Backward compatible bug fixes

## Upgrade Path

### From Previous Versions

When upgrading:

1. Review release notes for breaking changes
2. Backup database and files
3. Review [Installation & Upgrade](installation_upgrade.md) guide
4. Test in staging environment
5. Apply upgrade in production

### Migration Guide

For major version upgrades, see migration guides:

- Backup procedures
- Database migration steps
- Configuration changes
- Deprecated features

## Security Advisories

### Security Updates

Security updates are released as needed and documented here:

- **Date**: Date of security update
- **CVE**: CVE number if applicable
- **Severity**: Critical, High, Medium, Low
- **Description**: Description of vulnerability
- **Affected Versions**: Versions affected
- **Fix**: Version with fix

## Deprecation Notices

### Deprecated Features

Features marked for deprecation:

- **Feature**: Feature name
- **Version**: Version where deprecated
- **Removal**: Version where removed
- **Replacement**: Replacement feature or method

### Migration Path

For deprecated features:

1. Review deprecation notice
2. Update code to use replacement
3. Test changes
4. Remove deprecated code before removal version
