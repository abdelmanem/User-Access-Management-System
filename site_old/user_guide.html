2. Authentication & Session Basics

Templates: accounts/login.html, templates/navigation.html

  • Login screen enforces username + password with CSRF protection. Contact IT to provision accounts.
  • Post-login shell always renders the sidebar + top-bar layout from navigation.html.
  • Theme toggle and logout live in the sidebar footer; both rely on vanilla JS (`toggleTheme`) and Django's logout view.
  • Session timeouts respect Django settings; unsaved forms prompt the standard browser warning.

3. Dashboard Overview

Templates: templates/dashboard.html, analytics partials.

The dashboard aggregates KPI cards (users, systems, access assignments) plus trend charts. These values originate from `dashboard_home` view. Use it for a snapshot before diving into module-specific pages.

  • Quick Actions: Buttons linking directly to creation forms (user, system, access assignment).
  • Recent Activity: Derived from `AccessHistory` and user audit tables.
  • Compliance Widgets: When quarterly reviews or default-account remediation is overdue, cards link straight to the relevant reports.

4. Core Data Modules

4.1 Users

Templates: accounts/user_list.html, accounts/user_detail.html, accounts/user_form.html

  • Filters for status, department, and search across name/email/employee ID.
  • Bulk actions (activate/deactivate/export) map to the toolbar in user_list.html.
  • Detail view aggregates profile, employment data, system access (inline via `UserSystemAccess`).
  • Password resets and permission toggles use dedicated forms (`user_reset_password.html`, `user_permissions.html`).

4.2 Departments

Templates: departments/department_list.html, departments/department_form.html

  • Hierarchical parent selection supports org charts; nested departments show in the list view.
  • Each department detail page surfaces associated users to validate staffing vs. approvals.

4.3 Systems

Templates: systems/system_list.html, systems/system_form.html

  • Tracks metadata such as category, environment, support contacts, vendor.
  • Creation triggers default-account seeding via default_accounts.services.create_default_accounts_for_system.

4.4 Hardware

Templates: hardware/hardware_list.html, hardware/hardware_form.html

Optional module for device-level tracking (imaging, asset IDs) when tying workstation logins to access reviews.

5. Access Lifecycle & Compliance

5.1 Assignments & History

Templates: access_management/access_assignment_list.html, access_management/access_assignment_form.html, access_management/access_history_list.html

  • Create/edit assignments for each user ↔ system pair, capturing access type, request type, start/end dates, and approvals.
  • Status transitions (Pending → Active → Revoked) automatically log entries in access_history_list.html.
  • Bulk approval/rejection is available through the list toolbar for users with Access Administrator permissions.

5.2 Cross-System Visibility

Templates: access_management/cross_system_account_mapping.html, access_management/user_cross_system_accounts.html

  • Matrices display each employee's external usernames per system, including `is_generic_account` indicators.
  • Filters by department, system, review status, and export support (CSV/XLSX).

5.3 Generic Accounts & Policy Drift

Templates: access_management/generic_accounts_report.html, access_management/policy_drift_monitoring.html

  • Generic Accounts Report lists flagged usernames and provides remediation buttons (`mark_remediated.html`).
  • Policy Drift Monitor surfaces records lacking recent verification or missing usernames.

5.4 Quarterly Reviews & Compliance (4.5 & 4.6)

Templates: access_management/quarterly_access_reviews.html, access_management/bulk_quarterly_reviews.html, access_management/access_approval_compliance.html

  • Dashboard lists upcoming/due reviews with drill-down by system/owner.
  • Bulk workflow records confirmation for multiple accounts in a single submission.
  • Access Approval Compliance report reconciles approved vs. actual access & highlights remediation tasks.

5.5 Admin Accounts (4.3)

Template: access_management/admin_accounts_report.html

Provides dedicated listing for elevated privileges, including regular vs. admin usernames, password storage attestations, and workstation login indicators.

6. Default Account Management (PCI/RHG 4.7)

Templates: default_accounts/default_account_dashboard.html, default_accounts/default_account_detail.html, default_accounts/default_account_action_form.html, default_accounts/default_account_templates.html

This module inventories factory passwords, installer IDs, and RHG special accounts across every external system. It is fully documented in doc/DEFAULT_ACCOUNT_MANAGEMENT_4_7.md; highlights below focus on UI usage.

  • Dashboard & Registry: Summary cards + filterable table showing remediation progress. Exports to Excel via default_account_export.
  • Detail & Action Logging: Each record stores password change/removal timestamps, evidence references, and verification metadata. Logging an action automatically updates the parent record through `DefaultAccountAction.apply_to_account()`.
  • Template Catalog: Maintains canonical defaults per system type. Newly created systems seed records using default_accounts/services.py.
  • Seed Utility: `/default-accounts/seed/system/<id>/` back-fills historical systems.

7. Service & Privileged Accounts (4.2)

Templates: service_accounts/service_account_list.html, service_accounts/service_account_detail.html, service_accounts/service_account_compliance_report.html

  • Registry: Track non-human accounts with ownership, purpose, password last-changed, expiration, and compliance flags.
  • Password History: `service_account_password_history_form.html` records each rotation and automatically updates the parent entry.
  • Compliance Report: Highlights expiring or non-compliant credentials and supports Excel/PDF exports.
  • Attestation View: `service_account_attest.html` captures quarterly owner confirmation (if enabled in view).

8. Change Management & SOPs (4.4)

Templates: change_management/change_request_list.html, change_management/change_request_form.html

  • Log account creation/modification/deletion requests tied to systems and business justifications.
  • Capture system-owner approval, IT approval, and completion evidence.
  • Integrates with future modules (SOP repository, approvals surfaced inside cross-system matrix).

For SOP content, refer to doc/CHANGE_MANAGEMENT_4_4_PROCESS.md.

9. Import / Export & Reports

Data Import / Export

Templates: templates/data_import_export/home.html, templates/data_import_export/custom_export.html

  • Bulk CSV/XLSX export for Users, Departments, Systems, Access Assignments.
  • Import wizard enforces column mapping & validation rules (permissions: HR or Access Admin).
  • Custom Export builder supports ad-hoc filters for auditors.

Reports

Templates: templates/reports/*.html

  • Standard set: User Access Report, System Usage Report, Security Audit Report, Department Access Report.
  • All report tables offer CSV/PDF export and quick filters.

10. Audit, Search & Evidence

  • Audit Module: `accounts/user_deactivation_audit_list.html` and `accounts/user_archive_list.html` evidence user terminations and archival actions.
  • Global Search: Accessible via the sidebar link; view renders consolidated results (users/departments/systems/access). Supports partial matches and cross-field filtering.
  • Evidence Exports:
    • Default accounts → `/default-accounts/export/` (Excel).
    • Service accounts → compliance report export buttons.
    • Access assignments/history → list toolbar exports.

Detailed audit/control write-ups live beside this file under doc/*4_*.md (sections 4.1 – 4.7).
